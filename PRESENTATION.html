Decentralized Crypto Lottery

On-chain lottery on an EVM-compatible blockchain - smart contract, Rust backend indexer, and React dApp.

Live on Hardhat (local) & Sepolia testnet · All PRD requirements implemented & verified

What is DLottery?

Users buy numbered tickets (1-10) with the USD8 token. Each draw settles entirely on-chain - the smart contract holds and releases all funds and is the single source of truth.

Smart Contract

Solidity 0.8.28 + Hardhat. Rounds, tickets, settlement, prizes, refunds, rollover, DAO fee.

Backend

Rust (axum + alloy + sqlx). Passive event indexer + REST history API over Postgres.

Frontend

React + Vite + wagmi/viem. Wallet, live dashboard, purchase, draw, results, history.

Economics (PRD 5.4 - 5.6)

P_total = rollover + participants × ticketPrice

Net Profit = P_total − ticketPrice   (winner principal excluded)

DAO Fee = Net Profit × 5%  ·  Winner = P_total − DAO Fee

Backend - resilient indexer (BE-01 - BE-11)

Reliability

  • RPC retry + exponential backoff
  • Block confirmations before indexing
  • Chain reorg detection + rewind
  • Idempotent writes (tx_hash, log_index)

Security & honesty

  • Reentrancy-safe claims/refunds (checks-effects-interactions + guard), SafeERC20 transfers.
  • Strict access & one-shot guards: winner-only prize, refund once, one ticket per wallet.
  • Randomness is MVP-grade: uses block.prevrandao + draw salt - adequate for a testnet MVP but manipulable by block proposers.
  • Production path documented: swap _generateLuckyNumber for Chainlink VRF.

The limitation is called out in the contract header and the README - no hidden assumptions.
